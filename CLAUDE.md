# CLAUDE.md

Guidance for Claude Code when working in this repository.

## What this package is

`sheety_localization` is a Dart CLI package that turns a Google Sheet into
localization code. It ships two executables (see `pubspec.yaml`):

- **`localize`** (`bin/localize.dart`, backed by `lib/src/localize/`) — fills in
  missing translations in the sheet via the OpenAI API and writes them back.
- **`generate`** (`bin/generate.dart`, backed by `lib/src/generate/`) — reads
  the sheet, validates it and emits Flutter Dart (a drop-in replacement for
  `flutter gen-l10n` output plus a metadata API), TypeScript and Python code.
  It no longer writes ARB files and never runs `flutter`.

The sheet layout is `label | description | meta | <base> | <locale> ...`: row 1
is the header, the fourth column is the base/source language (not necessarily
English) and every column after it is a target locale. `README.md` is the user
documentation of the layout, the ICU subset, the fallbacks and every option.
Keep it in sync with behaviour changes.

## Architecture

```
bin/generate.dart            thin: runGenerate(args) + exit code
bin/localize.dart            CLI of localize
lib/sheety_localization.dart public barrel (localize API + runGenerate; tests
                             import the generate internals via test/sheety.dart)
lib/src/common/              shared by both executables
  sheet_layout.dart          sanitizer(), columnFromIndex(), isLocalizationHeader()
lib/src/localize/            the OpenAI translation pipeline (+ language_names.dart,
                             also used by the generate reader)
lib/src/generate/
  config.dart                CLI parser + sheety.yaml -> GenerateConfig (CLI wins)
  pipeline.dart              runGenerate: source -> reader -> validate -> emit ->
                             dart format -> writer; diagnostics output, exit codes
  source.dart                Google Sheets (read-only) and JSON snapshot sources
  reader.dart                sheets -> Catalog + diagnostics (locales, fallbacks,
                             synthetic parents, meta, duplicates)
  model.dart                 Catalog / Scope / Message / Translation / LocaleTag
  icu/                       ICU parser (gen-l10n semantics), mustache parser, AST
  cldr/                      CLDR plural data (generated by tool/cldr_plurals.dart)
                             + rule parser/evaluator, intl branch selection
  validate.dart, naming.dart cross-locale checks; per-target identifier rules
  diagnostics.dart           stable diagnostic codes (never rename an id)
  emitter.dart, targets.dart Emitter interface, Target, the registry of emitters
  emit/dart|ts|python/       one emitter per target language
  manifest.dart, writer.dart sheety_manifest.json; ownership-tracked writes, --check
tool/cldr_plurals.dart       regenerates cldr/plural_data.dart from cldr-core
test/fixtures/               small synthetic snapshots (no real data, ever)
test/golden/                 expected emitter output
example/                     sheety.yaml + snapshot.json + generated output of all
                             three targets (regenerate it when an emitter changes)
```

**Sheet interpretation must stay consistent.** `localize`
(`lib/src/localize/`) and the generate reader (`lib/src/generate/reader.dart`)
are separate code paths over the same sheet. Put shared rules (label sanitizing,
header detection, language names) in `lib/src/common/` or reuse them from
there. When you change how a sheet is read (header, locale codes, which sheets
count as localization sheets, labels, placeholders), update and test **both**,
plus the README.

Generated code must stay deterministic (byte-identical for unchanged input, no
timestamps) and self-contained (no runtime dependency on this package). After
any emitter change, regenerate the goldens and the example:

```sh
UPDATE_GOLDENS=1 dart test test/generate
dart run sheety_localization:generate --config=example/sheety.yaml
```

## Tests

```sh
dart test                          # unit + golden; integration tests skip missing tools
dart test -x integration           # without the integration tests
dart test --tags=integration       # only them (flutter analyze, tsc + node, python + mypy)
UPDATE_GOLDENS=1 dart test         # rewrite test/golden/** instead of comparing
```

Integration tests (tagged `integration`, see `dart_test.yaml`) skip themselves
when a toolchain is missing. Environment variables:

- `FLUTTER_ROOT`: Flutter SDK (default: from `flutter` on the `PATH`). Used for
  `flutter analyze` / `flutter test` of the Dart output and the gen-l10n parity
  test.
- `SHEETY_PYTHON`: interpreter used to compile and run the Python output
  (default `python3`; point it to a 3.9 to check the minimum version).
- `SHEETY_MYPY_PYTHON`: interpreter that has mypy (default: `SHEETY_PYTHON`
  when `-m mypy` works there).
- `SHEETY_PYRIGHT`: pyright executable (default `pyright` on the `PATH`).
- `SHEETY_REAL_SNAPSHOT`: path to a snapshot of the real production sheet.
- `SHEETY_REAL_REFERENCE`: path to the 0.6.0 + gen-l10n output for that snapshot
  (a Flutter package), for the parity tests.
- `SHEETY_DIAGNOSTICS_OUT`: file to write the full diagnostics of the real
  snapshot to.
- `SHEETY_KEEP_TMP=1`: keep the temporary TypeScript projects for inspection.
- `SHEETY_REQUIRE_TOOLS=1`: a missing toolchain fails the integration tests
  instead of skipping them (set in CI). `UPDATE_GOLDENS` is refused when `CI`
  is set.

The real sheet is internal: tests read it only through these variables and skip
without them. Never copy real data into the repository (fixtures, goldens or
`example/`).

## Release hygiene — required for every task/issue

Every change that touches shippable code MUST leave the package publishable.
Before finishing a task (and before opening a PR), you must:

1. **Bump the version** in `pubspec.yaml` following semver
   (`fix` → patch, new feature/relaxed constraint → minor, breaking → major).
   `generatorVersion` in `lib/src/generate/manifest.dart` must match it (a
   test enforces this), and the example output must be regenerated because the
   manifests record the version.
2. **Add a matching entry to `CHANGELOG.md`** under a new version heading, using
   the existing `**FIX** / **ADDED** / **CHANGED** / **BREAKING**` style.
3. **Verify the package still publishes** with:

   ```sh
   dart pub publish --dry-run
   ```

   It must report no errors (warnings that already existed on `master` are
   acceptable, but do not introduce new ones). `.pubignore` replaces
   `.gitignore` for pub. Anything secret or bulky must be listed there.

Skipping any of these makes the package impossible to publish, so treat them as
part of "done", not optional follow-up.

## Checks before opening a PR

```sh
dart format --set-exit-if-changed bin/ lib/ test/
dart analyze --fatal-infos --fatal-warnings bin/ lib/ test/   # must be clean
dart test                                                     # must be green
dart run sheety_localization:generate --config=example/sheety.yaml --check
dart pub publish --dry-run
```
